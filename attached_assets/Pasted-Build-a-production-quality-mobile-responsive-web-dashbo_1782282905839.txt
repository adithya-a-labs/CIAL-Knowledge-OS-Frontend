Build a production-quality, mobile-responsive web dashboard called “CIAL Knowledge OS” based on the two uploaded reference images. The final UI must look like an exact, polished replica of the generated images in layout, visual language, spacing, card style, sidebar, typography, CIAL green/white theme, rounded panels, airport imagery treatment, dashboard widgets, AI assistant screen, documents table, knowledge base page, assets page, and analytics page.

Important: The uploaded images are visual references only. Do not hardcode the images directly into the UI. Do not hardcode page content, stats, menu items, document rows, user details, cards, table fields, chart data, search suggestions, announcements, or dashboard blocks. Everything must be driven from configurable data objects, JSON files, constants, or mock API responses so that it can later be connected to a real backend.

Project goal:
Create a modular enterprise-grade dashboard UI for CIAL Knowledge OS, an AI-powered internal knowledge platform for Cochin International Airport. The system should help employees search SOPs, manuals, FAQs, engineering documents, asset knowledge, policies, and operational procedures using a clean CIAL-themed interface.

Tech stack:
Use React with TypeScript. Use Vite if needed. Use Tailwind CSS for styling. Use shadcn/ui-style components or clean reusable custom components. Use lucide-react icons. Use Recharts for analytics charts. The app must be componentized, scalable, and easy to extend.

Design direction:
Follow the uploaded images very closely. Use a clean white and soft green enterprise interface. The dashboard should feel modern, premium, calm, and trustworthy. It should use CIAL-inspired colors: olive green, lime green, deep forest green, soft mint backgrounds, white cards, subtle shadows, rounded corners, light borders, and clean spacing. Use a large left sidebar, a top-right user profile area, notification icon, help icon, and a dashboard content area. The UI should feel like an internal airport command/knowledge portal, not a generic SaaS dashboard.

Security requirements:
Although this is a frontend prototype, structure it like an enterprise app:

* Add route guards placeholder.
* Add role-based access control config.
* Create mock roles: admin, engineer, manager, viewer.
* Add permission checks for upload, delete, edit, admin settings.
* Do not expose secrets in frontend.
* Add .env.example for future API endpoints.
* Add comments explaining where real auth and backend integration will go.
* Add secure coding practices: no dangerouslySetInnerHTML, no hardcoded API keys, sanitize displayed user-generated text, and separate config from logic.
* Add audit log mock data for admin page.
* Design so Microsoft Entra ID or Keycloak can be integrated later.
